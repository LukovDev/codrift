# Codrift

3D-визуализатор структуры кода: C (а также C++, Java, C#, JavaScript/TypeScript и Python - см. «Языки»). Работает полностью в браузере: без бэкенда, без сборки, без записи файлов на диск. Подходит для GitHub Pages.

> Проект написан с помощью ИИ (Claude), но проверен и протестирован автором: каждое изменение проверялось в браузере на реальных проектах на разных языках.

- **Виды:** «Подключения» (`#include` / `import`: что файлу нужно при сборке, обычно заголовок), граф вызовов (функции или файлы: реальные вызовы между файлами реализации, мимо заголовков; две связи навстречу - файлы вызывают друг друга, например через указатели на функции), API заголовков (функции, макросы, типы, переменные → где объявлены и где реализованы), дерево директорий, статистика.
- **Источники:** публичный GitHub-репозиторий (опционально токен - хранится только в памяти вкладки), локальная папка (File System Access API или `webkitdirectory`), `.zip`, отдельные файлы.
- **Поиск и список узлов:** пустое поле поиска показывает все узлы текущего вида списком (на «Статистике» - все файлы и функции). Сортировка: по алфавиту, по длине имени, по числу строк, по числу связей; повторное нажатие меняет направление. С запросом - те же сортировки среди совпадений, точное совпадение имени всегда первое. Длинные списки подгружаются по мере прокрутки.
- **Фильтр на лету** (вкладка «Вид»): строка вида `src/core !tests` (слова и glob-маски - путь подходит, `!маска` - исключить) скрытие отдельных модулей и дерево папок с галочками (скрыть можно любую папку на любой глубине, например встроенную библиотеку). Граф перестраивается сразу, без повторного разбора; позиции узлов сохраняются. Фильтр относится к проекту: другой проект открывается без него, а если фильтр скрыл все узлы, появляется подсказка.
- **Обновление проекта:** кнопка ⟳ или клавиша `R` перечитывает источник (с текущими фильтрами из панели источника, даже не сохранёнными кнопкой); граф остаётся на экране, а ход обновления показывает тонкая шкала сверху с кнопкой «Отмена» (отменённое обновление оставляет проект как был). Загрузку тоже можно отменить - на экране загрузки по ссылке и в панели источника. Для папки, открытой через File System Access API, включено наблюдение: изменённые, новые и удалённые файлы подхватываются автоматически (проверка раз в 2,5 с, список файлов - раз в ~10 с).
- **Фильтры:** glob-списки «игнорировать» и «искать только в», расширения (по умолчанию пусто - языки определяются по файлам проекта; указали хоть одно расширение языка - берутся все его, например `.cpp` подтягивает `.hpp`), каталоги include. По умолчанию игнорируются служебные каталоги (`.git`, `.idea`, `__pycache__`, виртуальные окружения), результаты сборки (`build`, `dist`, `out`, `bin`, `target`, `cmake-build-*`), зависимости (`node_modules`, `vendor`, `third_party`, `external`, `libs`, `Pods` …), сгенерированный и минифицированный код (`*.min.js`, `*.pb.*`, `*.Designer.cs` …) и типичные встраиваемые библиотеки (`glad`, `stb_*`, `miniaudio.h`, папки `SDL*/`, `glfw/`, `cglm/`, `glm/`, `imgui/` …).
- **Документация:** описания берутся из комментариев над объявлениями (или в конце строки) и показываются в панели деталей. Экспорт в Markdown (весь проект / только заголовки / один файл).
- **Стили сцены - пресеты** «Простой», «Космос» и «Неон» (по умолчанию). Любой параметр пресета меняется вручную: палитра, форма узлов (сфера / кристалл / каркас), материал (матовый / мягкий / светящийся), ободок-контур (при любом материале), свечение (bloom), орбиты и электроны, импульсы (скорость и частота настраиваются), туман, тепловое дрожание, автовращение вокруг вертикали камеры, то есть по горизонтали экрана (скорость и задержка до начала настраиваются ползунками), фон (градиент / звёзды / процедурная туманность с новым «зерном» по кнопке / сетка).
- **Цвета:** узлы окрашены по типу, по модулю (папке проекта) или по метрике. Связь - градиент от цвета узла-источника к цвету узла-цели (у источника темнее - направление видно без стрелок). Внешние и «прочие» узлы на тёмной сцене светло-серые: свечение не превращает их в белые, их не спутать с яркими узлами кода. Галочка «Яркость по метрике» (вкладка «Вид», по умолчанию выключена) заставляет цвета модулей и типов вести себя как раскраска «по метрике»: мелкие и малосвязанные узлы - тёмный оттенок своего цвета, крупные - яркий. Шкала строится по рангу узла (а не по доле от максимума - один гигантский метод иначе сжимал её), а яркость применяется в шейдере уже после освещения. В «Неоне» основной цвет - синий из шкалы «по метрике»; «Сложение света» в нём по умолчанию выключено.
- **Производительность:** невидимые узлы и связи отбрасываются до отрисовки (frustum culling); кадры рисуются только при движении или анимации; без касаний фоновая анимация идёт на 30 к/с и засыпает после бездействия (по умолчанию через 60 с). Автовращение идёт на полном FPS и не засыпает, пока включено. Разрешение «Авто» само понижается при просадке FPS; «Максимум» - родное разрешение экрана (на телефонах ×3). Есть ограничение FPS (точное при любой частоте монитора - 60, 75, 144, 165 Гц), сглаживание MSAA (на компьютерах по умолчанию 4×: без него тысячи однопиксельных линий плотного графа мерцали при повороте камеры), счётчик FPS со временем кадра в миллисекундах (если FPS низкий, а миллисекунд мало - время уходит не на сайт, а на браузер); свечение считается в полном разрешении до 1080p, на больших экранах - с понижением (на телефонах - в 0.75, в режиме «Максимум» - всегда в полном). Узлы и связи рисуются несколькими вызовами отрисовки независимо от размера графа.
- **Видео и GIF** (вкладка «Экспорт»): квадратный ролик 480 / 720 / 1080 px, 15-60 кадров/с, 2-30 с; граф вращается вокруг вертикали камеры - ровно один оборот за ролик (бесшовный повтор) или с заданной скоростью. Кадры рендерятся по одному с точными метками времени, поэтому ролик плавный даже на тяжёлой сцене, а запись идёт быстрее реального времени (на CGDF MP4 720×720 на 8 с пишется ~1,2 с, GIF 480×480 на 4 с - ~1 с: палитра GIF подбирается раз в 20 кадров, надписи и легенда берутся из кэша, передышки браузеру - не чаще раза в 50 мс). Во время записи на экране виден квадратный кадр ролика (без растягивания) и шкала хода; страница перерисовывается примерно раз в 100 мс, поэтому шкала идёт вровень с записью. Запись можно отменить кнопкой в шкале хода. MP4 (H.264) пишется через WebCodecs и `mp4-muxer@5.1.3`, GIF - через `gifenc@1.0.3` (обе библиотеки подгружаются только при записи); если браузер не умеет WebCodecs, пишется GIF. Подписи узлов, пояснение цветов и заголовок рисуются поверх ролика по галочкам, как в PNG; подписи пересчитываются на каждом кадре под вращающуюся камеру.
- **Экспорт PNG:** масштаб 1×-4× (до 8192 px по стороне и ~16.7 Мпикс по площади - больше видеокарта может не выделить буферы; MSAA на время экспорта выключается, картинка и так сглажена размером), по выбору с подписями, легендой и заголовком.
- **Пресеты:** «Неон» - светящиеся кристаллы с импульсами на звёздном фоне; «Космос» - светящиеся ядра с оболочками и импульсами в туманности; «Простой» - без эффектов, в цветах темы сайта. Остальное (палитры «Сочная» и «Чертёж», сетка, туман и др.) настраивается вручную во вкладке «Стиль».
- **Косвенные вызовы:** вызовы через указатели на функции (`obj->field(...)`) связываются со всеми функциями, которые этому полю присваиваются: `x->field = fn`, `{ .field = fn }` или позиционный инициализатор `{ fn1, fn2 }` по порядку полей структуры. Кандидаты отбираются по числу аргументов. Например, в игровом движке так видно, что главный цикл вызывает `start/update/render…` всех сцен.
- **Камера:** плавное орбитальное управление: по умолчанию свободное вращение (без «верха» и «низа»), по галочке во вкладке «Экран» - классическое (горизонт ровный, наклон до ±89°), перелёт к узлу с центрированием, сдвиг изображения под панель деталей, изометрическая проекция с плавным переходом (кнопка на панели справа или вкладка «Экран»).
- **Выделение:** выделенный узел, его соседи и их связи остаются как есть, а остальные узлы плавно гаснут и становятся полупрозрачными (цвет к фону, ободок и свечение - к минимуму, часть пикселей отбрасывается по шаблону - без сортировки тысяч узлов; каркасы внешних функций - почти прозрачные, а не тёмные пятна поверх связей), так же гаснут их связи и импульсы, и так же плавно возвращаются после снятия выделения. Встречные связи (A → B и B → A) всегда рисуются дугами в разные стороны (точно та же кривая, что у выделенных связей библиотеки, - стрелки идут по дуге), импульсы бегут по дуге, а стрелки не упираются друг в друга; что значит стрелка в текущем виде - написано в легенде. Смена вида («Вызовы», API …) сбрасывает выделение и показывает граф целиком; переход «к файлу» из панели деталей выделяет нужный узел в другом виде. Пока граф собирается, выделение ничего не гасит, а выделенные связи и их импульсы не показываются (иначе они торчали бы к ещё не выросшим узлам, а погашенный граф выглядел тёмными линиями поверх ореола); после сборки остальное гаснет, а выделенные связи со стрелками проявляются одной плавной анимацией (~0,5 с), так же, как при обычном выделении. Доля связей с фоновыми импульсами (бюджет - 30 тысяч точек) меняется плавно, а у порога импульсы связи гаснут постепенно. У узла с сотнями связей (больше 120) их не рисует библиотека отдельными объектами - они идут одним отдельным слоем линий со своей непрозрачностью (в общем буфере плотного графа линии почти прозрачны, и выделенные связи пропадали под некоторыми углами), а подписей не больше «Количества подписей»: на Mindustry выделение `Blocks.java` (646 связей) замедляло кадр с 10 до 60 мс. Длинные списки в панели деталей и статистике дописываются кнопкой «… ещё N», пустые разделы диагностики не раскрываются. Камера, подлетевшая к выделенному узлу, следует за ним, пока раскладка его двигает (сдвиг камеры вручную слежение снимает). Кнопка «Показать всё» при выделенном узле возвращает камеру к нему, без выделения - показывает весь граф.
- **Построение:** граф разрастается от «главного» узла: в «Директориях» - от корня проекта, в API - от заголовка с наибольшим числом объявлений, в «Подключениях» и «Вызовах» - от узла, к которому ведёт больше всего связей (общий заголовок, базовая функция). Начальные места для раскладки тоже идут от него (каждый узел рядом со своим родителем по обходу связей - без плоской «решётки» d3 в первую секунду), а волна появления - пространственная: шар, расширяющийся от главного узла; узел вырастает почти на своём месте, а связь проявляется, когда оба её конца почти выросли. Раньше волна шла по обходу связей и в плотном графе сразу зажигала узлы по всему объёму - связи между ними складывались в рваный многогранник. При фильтре и переключении модулей стоящие узлы остаются на местах, новые вырастают из соседей, подписи и панель деталей не пересоздаются.
- **Пауза** (кнопка ⏸) замораживает раскладку и останавливает рождение импульсов: уже летящие долетают до конца связи, после «продолжить» новые появляются снова. «Продолжить» не встряхивает граф: раскладка идёт дальше с той силы, на которой остановилась, а если она уже успокоилась - узлы остаются на местах. В дереве уровни при этом остаются закреплёнными. На паузе раскладка останавливается сразу (и в потоке, и в библиотеке).
- **Подписи** (до 1000): без выделения подписываются самые связанные узлы (галочка во вкладке «Экран» переключает на ближайшие к камере), при выделении - только выделенный узел и его соседи. Ближние подписи и узлы скрывают дальние подписи, которые они перекрывают; проверка идёт по сетке экрана и почти ничего не стоит.
- **Раскладка в отдельном потоке:** физика «сил» считается в Web Worker, основной поток только переносит позиции. На графе из 3000 узлов кадр во время раскладки стал легче в ~13 раз (3.5 мс вместо 45). Дерево и радиальная раскладка тоже считаются в потоке - мягкими силами к уровню (высота или радиус сферы), а уровни - обходом в ширину от корней (узлов без входящих связей; узлы в циклах - на уровень ниже уже пройденных предков); корни радиальной раскладки стоят на своей сфере, а не в центре. Иерархию библиотеки сайт использует, только если поток не запустился. Трение по умолчанию небольшое, и граф успевает равномерно разрастись; по мере остывания трение растёт, поэтому плотный ком не колышется, как капля. Когда сила раскладки ослабла и узлы полсекунды подряд движутся медленнее порога, трение за ~1,5 с плавно (по S-кривой) растёт, узлы тормозят до нуля и раскладка останавливается сама, не по таймеру. Порог настраивается ползунком «Порог остановки» во вкладке «Физика» (0 - только когда силы полностью иссякнут). В очень плотных графах (десятки связей на узел, как подключения Java-проекта) линии связей сами приглушаются - иначе десятки тысяч линий сливаются в сплошное пятно, за которым не видно узлов. Плотные места не слипаются: отталкивание узла растёт со степенью (под корнем) и с плотностью графа (связей на узел), длина связи - со степенями её концов. Узлы не пересекаются: столкновения расталкивают их сферы (с запасом на дрожание), в том числе после смены размера узлов, а во время торможения и после остановки оставшиеся пересечения разводятся напрямую по позициям - узлы не застревают друг в друге, даже если их стягивают сильные связи. На больших графах дальнее отталкивание считается грубее - шаг быстрее при том же виде. Смена раскладки (силы / дерево / радиально) плавная, камера сама подстраивается под новую форму (после загрузки, смены вида или раскладки - только если камеру не двигали, пока граф раскладывался): трение после мягкого старта спадает постепенно, узлы переходят к новым местам с текущих, повторный клик по выбранной раскладке её не перезапускает. Радиальная раскладка расширяется с числом узлов, чтобы большой граф не сбивался в ком. Переключатель раскладки - во вкладке «Физика»; по умолчанию «Дерево» в «API» и «Директориях», «Силы» - в «Подключениях» и «Вызовах». Позиции из потока сглаживаются: поток присылает их неравномерно (перегружен - реже и рывками), а каждый кадр узел проходит долю пути к последней присланной позиции (экспонента с постоянной времени порядка интервала между сообщениями) - движение не замирает и не дёргается (на Mindustry замираний и рывков стало в 15 и 5 раз меньше). Прогрев раскладки перед первым кадром - не дольше 150 мс: на огромном виде граф появляется через ~0,3 с после смены вкладки, а не через несколько секунд пустого экрана.
- **Открытие по ссылке** (`?repo=…` или `?snap=…`): пока данные загружаются, показывается экран загрузки с ходом работы - интерфейс закрыт, чтобы до готовности графа ничего не нажать. Если загрузить не удалось, открывается панель источника с ошибкой.
- **Кадр на больших графах:** радиусы узлов кэшируются, матрицы пишутся прямо в буфер, связи не проходят отсечение (видеокарта рисует десятки тысяч отрезков почти даром), их цвета выгружаются только при изменении, а импульсов не больше 30 тысяч точек. На Mindustry (8805 узлов, 31 тысяча связей) кадр стал легче примерно в полтора раза.
- **Камера при быстром вращении** не разворачивается в обратную сторону: цель поворота не уходит от камеры дальше ~150°, камера подтягивается следом.
- **Смена и обновление проекта:** после загрузки другого проекта или перечитывания текущего камера показывает граф целиком. Если при обновлении (кнопкой, клавишей R или наблюдателем за папкой) выделен узел и он остался в проекте, камера не трогается: ни масштаб, ни ракурс не меняются.
- **Интерфейс:** английский по умолчанию (кнопка RU/EN переключает и запоминает выбор), плавные анимации панелей, вкладок и списков.
- **Настройки:** вкладка «Вид» - фильтр, цвет (тип / модуль / метрика, «Яркость по метрике»), размер узлов (по умолчанию - сумма размеров по строкам и по числу связей) и опции вида; «Стиль» - пресет и его параметры; «Экран» - подписи, камера, производительность, тема; «Физика» - раскладка (силы / дерево / радиально) и силы (отталкивание, длина связей, притяжение, трение, порог остановки); «Экспорт» - Markdown, PNG, видео, снимок, графы. Кнопка «Сбросить вкладку» возвращает значения по умолчанию только своей вкладки.
- **Статистика:** карточки (строки, код, комментарии, функции, доля документированных функций, медиана длины функции, функции длиннее 50 строк, средний файл и др.), графики, таблицы по директориям и файлам, топы и диагностика. Открытая панель источника не накрывает статистику: содержимое плавно сдвигается вправо (анимация сдвига, без рывка), а на узкой странице графики встают в одну колонку. Графики (SVG, цвета темы интерфейса; при наведении - подсказка, щелчок по точке или плитке - переход к узлу на графе):
  - **Карта кода** (treemap): площадь плитки - строки кода; крупные папки до трёх уровней показывают содержимое, цепочки из одной папки (`core/src/mindustry/`) схлопываются в одну плитку. Щелчок по папке - внутрь (путь сверху - назад), по файлу - к файлу на графе. Раскраска: «папки» (свой цвет у каждой папки верхнего уровня) или «комментарии» (от красного - без комментариев, до зелёного - от 25%).
  - **Состав кода:** кольцо по языкам (или по модулям в одноязычном проекте) и полоса «код / комментарии / пустые».
  - **Модули:** объём кода и доля функций с описанием в каждом модуле.
  - **Длина функций** и **размер файлов:** гистограммы с медианой и 90-м перцентилем; длинные - оранжевые и красные; щелчок по столбцу - список функций или файлов этого размера.
  - **Размер и комментарии:** точка - файл (размер и плотность комментариев), красная зона - крупные файлы почти без комментариев.
  - **Связанность функций:** точка - функция (скольких вызывает и сколько вызывают её), справа сверху - узлы, изменение которых затронет многое; цвет - длина.
  - **Зависимости файлов:** сколько файлов подключает файл и сколько подключают его - стабильные, зависимые и узлы зависимостей.
  - **Концентрация кода** (кривая Парето): какая доля файлов содержит половину и 80% кода.

  На большом проекте (Mindustry: 871 файл, 9773 функции) статистика строится примерно за 0,1 с: данные графиков считаются один раз на проект, точки в одном месте экрана объединяются, таблица файлов показывает первые 200 строк (остальные - по кнопке), списки диагностики строятся при раскрытии, а сортировка, раскрытие папок и щелчки по графикам перерисовывают только свою часть страницы.

## Запуск

Выложите папку на GitHub Pages или запустите локально любой статический сервер в этой папке, например `python -m http.server 8000`, и откройте `http://localhost:8000/`. Открытие `index.html` через `file://` тоже работает (библиотеки берутся с CDN), но браузер не даёт такой странице менять свой адрес - состояние тогда не попадает в адресную строку; ссылку на вид можно получить кнопкой «Скопировать ссылку».
Ссылки вида `index.html?repo=owner/repo&ref=branch&view=calls` сразу загружают репозиторий.

### Телефон и веб-приложение

Сайт можно добавить на экран «Домой» (Safari: «Поделиться → На экран „Домой“», Chrome: «Установить приложение») - он откроется на весь экран со своим значком (`manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png`). Сверху оставлен отступ под строку состояния и Dynamic Island, снизу - под полосу жестов. Страница не масштабируется щипком и двойным тапом, поля ввода не увеличивают её при фокусе - масштабируется только сам граф. Шторку деталей можно тянуть: вверх - развернуть, вниз - свернуть или закрыть.

### Состояние в ссылке

Адресная строка всегда содержит текущее состояние, поэтому ссылку можно просто скопировать. Кнопка «Скопировать ссылку на вид» добавляет ещё и камеру. В ссылку попадает только то, что отличается от значений по умолчанию.

| Параметр | Что задаёт | Пример |
|---|---|---|
| `repo`, `ref` | репозиторий GitHub и ветку | `repo=DaveGamble/cJSON&ref=master` |
| `snap` | снимок `.drift` по ссылке (вместо `repo`) | `snap=project.drift` |
| `view` | вид: `includes`, `calls`, `api`, `dirs`, `stats` | `view=calls` |
| `vo` | опции видов `вид.ключ:значение` | `vo=calls.layout:td,calls.showExt:1` |
| `style` | пресет: `simple`, `cosmos`, `neon` | `style=neon` |
| `vs` | отличия от пресета `ключ:значение` | `vs=bloom:0,glow:1.2,sky:stars` |
| `lk` | подписи по типам узлов | `lk=ext:1,macro:0` |
| `lf`, `hm`, `hd` | фильтр на лету, скрытые модули и папки | `lf=src/core !tests&hm=tests&hd=src/libs` |
| `ign`, `only`, `exts`, `roots`, `maxkb`, `maxf` | фильтры файлов (списки через `;`) | `only=src/core` |
| `sel`, `focus` | выделенный узел и показ только его окрестности (глубина) | `sel=fn:main@src/main.c&focus=1` |
| `cam` | камера: кватернион поворота и приближение (старый формат из трёх чисел тоже читается) | `cam=0.1,0.3,0,0.95,0.8` |
| `lang`, `theme` | язык и тема | `lang=en&theme=dark` |
| `embed` | режим встраивания в iframe (без панели источника) | `embed=1` |

### Снимки и экспорт

- **Снимок проекта `.drift`** (вкладка «Экспорт») - сжатый gzip JSON: результат разбора, раскладка текущего вида и настройки, по желанию с исходным кодом. Можно сохранить и без сжатия (`.drift.json`). Открывается во вкладке «Снимок» панели «Источник» (из файла или по ссылке), перетаскиванием на страницу или ссылкой `?snap=путь/к/файлу.drift`. Снимки прежнего формата `.ccv` тоже открываются. Повторного разбора и запросов к GitHub не нужно; раскладка восстанавливается точно.
- **Граф текущего вида:** GLB (3D-модель для Blender, узлы - именованные объекты), GEXF (Gephi, с позициями и цветами), GraphML (yEd, Cytoscape), DOT (Graphviz), JSON.

Зависимости (CDN jsDelivr, версии зафиксированы): `three@0.174.0` (вместе с `UnrealBloomPass`), `3d-force-graph@1.77.0`; `fflate@0.8.2` подгружается только для zip, `mp4-muxer@5.1.3` и `gifenc@1.0.3` - только для записи видео. Сборка `three/webgpu`, которую 3d-force-graph тянет ради неиспользуемого WebGPU-рендера, заменена заглушкой через import map: вторая копия Three.js не выполняется (jsDelivr всё равно предзагружает файл заголовком `Link: modulepreload`, после первого визита - из кэша). Страница, открытая как файл (`file://`), запускает поток раскладки из `data:`-адреса (blob-адрес там запрещён); если и это не удалось, раскладка считается в основном потоке.

| | Мышь | Тач |
|---|---|---|
| Вращение | левая кнопка | один палец |
| Сдвиг | правая/средняя кнопка или Shift + левая | два пальца |
| Масштаб | колесо | щипок |
| Выбор узла | клик | тап |
| Список узлов | клик в пустое поле поиска | тап в пустое поле поиска |

`/` - фокус в поиск, `Esc` - отменить запись ролика или загрузку, закрыть настройки / снять выделение, `R` - обновить проект.

Панель настроек закрывается тапом или кликом в любом месте вне неё, в том числе по графу (такой тап только закрывает панель и не выбирает узел). Вращение и масштаб графа панель не закрывают - можно настраивать и сразу смотреть результат.

## Парсер

`parser.js` - лёгкий эвристический разбор без препроцессора: корректно вырезает комментарии и литералы, разбирает `#include`/`#define`, условную компиляцию (`#if 0` и `#else`-ветки не участвуют в разборе тел), объявления и определения функций (включая C23-атрибуты `[[...]]`), `struct/union/enum/typedef`, глобальные переменные и вызовы внутри тел функций. Вызовы через макросы разворачиваются до реальных функций.

Ограничения: код, генерируемый макросами (например, функции, объявленные через `DEFINE_X(name)`), не распознаётся. Вызов через указатель на функцию, который хранится в локальной переменной или параметре, не разрешается. Через поля структур - разрешается, см. «Косвенные вызовы».

## Языки

Разбор подключается плагинами (`langs.js`, реестр `CodriftLangs`); язык файла определяется по расширению. Если файлов выбранных расширений нет, сайт сам определяет основные языки проекта. Галочки языков в фильтрах источника добавляют или убирают их расширения.

| Язык | Расширения | Связи «импорта» |
|---|---|---|
| C | `.c .h` | `#include` |
| C++ | `.cpp .cc .cxx .c++ .hpp .hh .hxx .h++ .ipp .tpp .inl .ixx .cppm` (и `.h`, если в проекте есть C++) | `#include` |
| Java | `.java` | `import` → файл класса (и `pkg.*`) |
| C# | `.cs` | `using` → файлы пространства имён |
| JS / TS | `.js .jsx .mjs .cjs .ts .tsx .mts .cts` | `import`, `require`, `export … from` (относительные пути) |
| Python | `.py .pyi .pyw` | `import`, `from … import` (абсолютные и относительные) |

Функции получают имя `Класс.метод`; вызовы `this.f()`/`self.f()` связываются с методом своего класса, конструкторы - с `new Foo()`/`Foo()`. Вызов параметра-колбэка (`fn()`, `cb()`) не путается с одноимённой функцией проекта, вызовы разрешаются только внутри своего языка (C и C++ видят друг друга). Макросы экспорта (`class SPDLOG_API logger`) пропускаются, шаблоны и обобщения (`template<class T>`, `foo<T>(x)`) понимаются.

Новый язык - объект `{ id, name, exts, parse(path, text), isHeader?, hasHeaders, oop, resolveImport?(file, imp, ctx) }`, зарегистрированный через `CodriftLangs.register(...)`. Для C-подобного синтаксиса есть конструктор `makeBraceLang(cfg)`. `parse` возвращает тот же формат, что и `CParser.parseFile`: `includes`, `funcs` (с `name`, `container`, `sig`, `calls`, `ids`, `memberCalls`, `doc`), `types`, `vars`, `macros`, `decls`.

## Лимиты GitHub

Без токена GitHub API даёт 60 запросов в час на IP. На одну загрузку уходит один запрос (дерево файлов), а содержимое читается через `raw.githubusercontent.com`. С токеном всё идёт через API. Если лимит исчерпан, список файлов берётся через jsDelivr (ветки `main` / `master` или указанная), содержимое - как обычно. jsDelivr не отдаёт репозитории больше 50 МБ - тогда нужен токен или подождать сброса лимита.
