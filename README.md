# Codrift

**3D-карта кода проекта прямо в браузере.** Codrift разбирает исходники и показывает их как интерактивный граф: какие файлы друг друга подключают, какие функции кого вызывают, где объявлен и где реализован API, как устроены папки, и подробную статистику с графиками.

- **Языки:** C, C++, Java, C#, JavaScript / TypeScript, Python.
- **Источники:** публичный репозиторий GitHub, локальная папка, `.zip`, отдельные файлы или готовый снимок `.drift`.
- **Без сервера:** весь разбор идёт в браузере, код никуда не отправляется (кроме запросов к GitHub за файлами). Сайт - статические файлы, подходит для GitHub Pages.

Сайт: **[codrift.lukovdev.ru](https://codrift.lukovdev.ru)** · пример: [Mindustry](https://codrift.lukovdev.ru/?repo=Anuken/Mindustry&view=includes)

> Проект написан с помощью ИИ (Claude), но проверен и протестирован автором: каждое изменение проверялось в браузере на реальных проектах на разных языках.

## Быстрый старт

1. Откройте сайт и нажмите «GitHub-репозиторий…» (или выберите пример), «Локальная папка…» или «Открыть файл снимка…». Файл `.drift` или `.zip` можно просто перетащить на страницу.
2. Граф разрастается от главного узла проекта и сам раскладывается. Щелчок по узлу - подробности в панели справа.
3. Вкладки сверху переключают вид, кнопка ☰ слева открывает источник, кнопка настроек справа внизу - все параметры.

Ссылка вида `?repo=owner/repo&ref=ветка&view=calls` сразу открывает репозиторий.

### Свой экземпляр

Это статический сайт без сборки: выложите папку на GitHub Pages или запустите любой статический сервер в папке проекта, например `python -m http.server 8000`, и откройте `http://localhost:8000/`.

`index.html` можно открыть и просто как файл (`file://`) - библиотеки берутся с CDN. Но такой странице браузер не даёт менять свой адрес, поэтому состояние не попадает в адресную строку; ссылку на вид даёт кнопка «Скопировать ссылку на вид».

### Телефон

Сайт можно добавить на экран «Домой» (Safari: «Поделиться → На экран „Домой“», Chrome: «Установить приложение») - он откроется на весь экран со своим значком. Страница не масштабируется щипком и двойным тапом - масштабируется только граф. Панель деталей на телефоне - шторка снизу: вверх - развернуть, вниз - свернуть или закрыть.

## Виды

| Вид | Узлы | Связь A → B |
|---|---|---|
| **Подключения** | файлы | A подключает B (`#include`, `import`, `using` и т.п.) |
| **Вызовы** | функции и методы (или целые файлы) | A вызывает B |
| **API** | файлы и объявленные в них функции, типы, переменные, макросы | заголовок → объявление → файл реализации (в языках без заголовков - файл → его классы и методы) |
| **Директории** | папки и файлы | папка → содержимое |
| **Статистика** | - | карточки, графики, таблицы и диагностика (см. [Статистика](#статистика)) |

Особенности видов:

- **Вызовы.** Детализация «Функции» или «Файлы» (связь = функции файла A вызывают функции файла B). Отдельно включаются:
  - ссылки на функции без вызова (`&fn`, колбэки);
  - косвенные вызовы через указатели на функции;
  - макросы как узлы (без них вызов через макрос сразу ведёт к функциям, которые макрос вызывает);
  - внешние функции (libc, SDL…).
- **Подключения.** Можно показать внешние подключения (системные заголовки, `java.util`, `numpy`…) и файлы сторонних библиотек, которые лежат в проекте, но исключены фильтром.
- **Косвенные вызовы (C).** Вызов `obj->field(...)` связывается со всеми функциями, которые этому полю присваиваются: `x->field = fn`, `{ .field = fn }` или позиционный инициализатор `{ fn1, fn2 }` по порядку полей структуры. Кандидаты отбираются по числу аргументов. Например, в игровом движке видно, что главный цикл вызывает `start/update/render…` всех сцен.
- **Встречные связи.** A → B и B → A рисуются дугами в разные стороны, чтобы стрелки не упирались друг в друга. Что значит стрелка в текущем виде, написано в легенде внизу.

## Работа с графом

- **Выделение.** Щелчок по узлу выделяет его: соседи и связи остаются яркими, остальное плавно гаснет. Связи выделенного узла рисуются со стрелками и бегущими импульсами, камера подлетает к узлу и следует за ним, пока раскладка его двигает. В панели деталей:
  - описание из комментариев, сигнатура и код;
  - кто кого подключает и вызывает, со ссылками на другие узлы и виды;
  - кнопки «Камера к узлу», «Ссылка» (на этот узел), «Только окрестность», «Markdown» (для файла) и «Открыть на GitHub».
- **Поиск и список узлов.** Пустое поле поиска показывает все узлы текущего вида списком (на «Статистике» - все файлы и функции). Сортировка по алфавиту, длине имени, строкам или связям; повторное нажатие меняет направление. Точное совпадение имени всегда первое.
- **Фильтр на лету** (настройки → «Вид»). Строка вида `src/core !tests` (glob-маски, `!` исключает), чипы модулей и дерево папок с галочками. Граф перестраивается сразу, без повторного разбора, узлы остаются на местах. Фильтр относится к проекту: другой проект открывается без него.
- **Сборка графа.** Граф разрастается шаром от «главного» узла:
  - в «Директориях» - от корня проекта;
  - в API - от заголовка с наибольшим числом объявлений;
  - в «Подключениях» и «Вызовах» - от узла, к которому ведёт больше всего связей.

  При фильтре новые узлы вырастают рядом с соседями.
- **Раскладки** (настройки → «Физика»): «Силы» (физическая модель), «Дерево» (уровни по направлению связей) и «Радиально» (уровни - концентрическими сферами). По умолчанию «Дерево» в «API» и «Директориях», «Силы» - в остальных видах. Смена раскладки плавная. Раскладка останавливается сама, когда узлы почти перестают двигаться (ползунок «Порог остановки»).
- **Пауза** (⏸) замораживает раскладку и останавливает рождение импульсов. «Продолжить» не встряхивает граф, а продолжает с того места, где он был.
- **Обновление** (⟳ или клавиша `R`). Перечитывает источник; граф и выделение остаются на месте, а ход показывает тонкая шкала сверху с кнопкой «Отмена». Для папки, открытой через File System Access API, можно включить слежение: изменённые, новые и удалённые файлы подхватываются сами (проверка раз в 2,5 с).
- **Подписи.** Без выделения подписываются самые связанные узлы (или ближайшие к камере - галочка во вкладке «Экран»), при выделении - узел и его соседи. Подписи, закрытые ближними узлами и подписями, прячутся.
- **Камера.** По умолчанию свободное вращение без «верха» и «низа», по галочке - классическое с ровным горизонтом. Есть плавный переход к изометрической проекции (кнопка справа). «Показать всё» при выделении возвращает камеру к узлу, без выделения - показывает весь граф. Когда сцену не трогают, через несколько секунд включается автовращение.

## Источники и фильтры файлов

Панель «Источник» (кнопка ☰):

- **GitHub** - публичный репозиторий (`owner/repo` или ссылка), ветка / тег / коммит. Токен GitHub необязателен, хранится только в памяти вкладки и снимает лимит запросов (см. [Ограничения](#ограничения)).
- **Папка / zip** - локальная папка (File System Access API или выбор папки), архив `.zip` или отдельные файлы.
- **Снимок** - файл `.drift` или ссылка на него (см. [Экспорт](#экспорт)).

Загрузку можно отменить на экране загрузки, в панели источника или клавишей `Esc`.

**Фильтры файлов:**

- **«Игнорировать» и «Искать только в».** Это glob-списки, по маске на строку. По умолчанию игнорируются:
  - служебные каталоги (`.git`, `.idea`, `__pycache__`, виртуальные окружения);
  - результаты сборки (`build`, `dist`, `bin`, `target`, `cmake-build-*`…);
  - зависимости (`node_modules`, `vendor`, `third_party`, `external`, `libs`…);
  - сгенерированный и минифицированный код (`*.min.js`, `*.pb.*`, `*.Designer.cs`…);
  - типичные встраиваемые библиотеки (`glad`, `stb_*`, `miniaudio.h`, `SDL*/`, `glfw/`, `glm/`, `imgui/`…).
- **Расширения и языки.** По умолчанию пусто: языки определяются по самым частым файлам проекта. Если указать хоть одно расширение языка, берутся все его расширения (`.cpp` подтягивает `.hpp`).
- **Каталоги подключаемых файлов C/C++** (`auto` - найти самим), максимальный размер файла и число файлов.

## Настройки

Кнопка настроек (справа внизу) открывает панель с вкладками. «Сбросить вкладку» возвращает значения по умолчанию только текущей вкладки, «Сбросить всё» - всем.

| Вкладка | Что настраивается |
|---|---|
| **Вид** | фильтр на лету, модули и папки; цвет узлов (по типу / модулю / метрике, «Яркость по метрике»); размер узлов (строки + связи / строки / связи / одинаковый); опции текущего вида |
| **Стиль** | пресет и все его параметры: палитра, форма и материал узлов, ободок, светимость, дрожание, орбиты, связи и их свечение, импульсы, bloom, фон, туман, автовращение |
| **Экран** | размер и качество узлов, стрелки и анимация выделения, подписи, камера и проекция, ограничение FPS, разрешение рендера, сглаживание MSAA, сон анимации, счётчик FPS, тема |
| **Физика** | раскладка (силы / дерево / радиально), отталкивание, длина связей, притяжение к центру, трение, порог остановки, расстояние между уровнями |
| **Экспорт** | Markdown, PNG, видео и GIF, снимок проекта, файлы графа |

Почти у каждой настройки есть подсказка «?» с объяснением.

## Стили и цвета

**Пресеты:**

- **Неон** (по умолчанию) - светящиеся кристаллы с импульсами на звёздном фоне.
- **Космос** - светящиеся ядра с оболочками и импульсами в туманности.
- **Простой** - без эффектов, в цветах темы сайта.

Любой параметр пресета меняется вручную во вкладке «Стиль»:

- палитра: Тема, Сочная, Космос, Неон, Чертёж;
- форма узлов: сфера, кристалл, каркас;
- материал: матовый, мягкий, светящийся;
- фон: градиент, звёзды, процедурная туманность (с новым «зерном» по кнопке), сетка;
- орбиты с электронами, туман глубины, сложение света и др.

**Цвета:**

- Узлы окрашены по типу, по модулю (папке проекта) или по метрике (строки / связи).
- Связь - градиент от цвета узла-источника к цвету узла-цели; у источника она темнее, поэтому направление видно и без стрелок.
- Внешние и «прочие» узлы на тёмной сцене светло-серые.
- Галочка «Яркость по метрике» (по умолчанию выключена) делает мелкие и малосвязанные узлы тёмным оттенком своего цвета, а крупные - ярким.

Интерфейс сайта - светлая или тёмная тема (как в системе или вручную), английский или русский язык (кнопка RU / EN).

## Статистика

**Карточки:**

- файлы, строки, код, комментарии, пустые строки, плотность комментариев;
- функции, доля документированных функций, медиана длины функции, функции длиннее 50 строк;
- средний файл, типы, подключения между файлами;
- макросы (если они есть).

**Графики** (при наведении - подсказка, щелчок по точке или плитке - переход к узлу на графе):

- **Карта кода** - плитки размером со строки кода; крупные папки показывают содержимое до трёх уровней вглубь. Щелчок по папке - внутрь, по файлу - к нему на графе. Раскраска «папки» или «комментарии» (от красного - без комментариев - до зелёного).
- **Состав кода** - кольцо по языкам (или модулям) и полоса «код / комментарии / пустые».
- **Модули** - объём кода и доля функций с описанием в каждом модуле.
- **Длина функций** и **размер файлов** - гистограммы с медианой; щелчок по столбцу - список.
- **Размер и комментарии** - файлы по размеру и плотности комментариев; красная зона - крупные файлы почти без комментариев.
- **Связанность функций** - скольких функция вызывает и сколько вызывают её; справа сверху - узлы, изменение которых затронет многое.
- **Зависимости файлов** - стабильные, зависимые и узловые файлы.
- **Концентрация кода** - кривая Парето: какая доля файлов содержит половину и 80% кода.

**Таблицы и списки:**

- дерево директорий со строками кода, комментариями и пустыми строками;
- сортируемая таблица файлов с фильтром;
- топы: самые длинные функции, чаще всего подключаемые файлы, чаще всего вызываемые функции и функции с наибольшим числом исходящих вызовов.

**Диагностика:**

- функции, которые не вызываются внутри проекта;
- циклы подключений;
- для C/C++ ещё прототипы без определения, функции без прототипа в заголовке и заголовки, которые никто не подключает.

## Экспорт

Вкладка «Экспорт» в настройках:

- **Markdown-документация** - весь проект, только API или один файл (кнопка в панели деталей файла). Внутри дерево папок, статистика и по каждому файлу: подключения, функции с сигнатурами и описаниями из комментариев, кто кого вызывает, типы, макросы, переменные. Блоки кода подсвечены по языку файла, методы подписаны с классом. «Только API» - это заголовки C/C++, а в остальных языках - публичные классы и методы.
- **PNG** - масштаб 1×-4× (до 8192 px по стороне), по выбору с подписями узлов, пояснением цветов и заголовком.
- **Видео и GIF:**
  - квадратный ролик 480 / 720 / 1080 px, 15-60 кадров/с, 2-30 с;
  - граф делает ровно один оборот (бесшовный повтор) или вращается с заданной скоростью;
  - кадры рендерятся по одному, поэтому ролик плавный даже на тяжёлой сцене, а запись обычно идёт быстрее реального времени;
  - подписи, легенда и заголовок - по галочкам;
  - MP4 (H.264) пишется через WebCodecs, а если браузер их не умеет - GIF;
  - запись можно отменить.
- **Снимок проекта `.drift`:**
  - что внутри: результат разбора, раскладка текущего вида и настройки, по желанию с исходным кодом; файл сжат gzip, можно сохранить и без сжатия (`.drift.json`);
  - открывается мгновенно, без повторного разбора и без GitHub: из панели «Источник», перетаскиванием или ссылкой `?snap=путь/к/файлу.drift`;
  - удобно положить снимок рядом с сайтом своего проекта.
- **Граф текущего вида:** GLB (3D-модель для Blender, узлы - именованные объекты), GEXF (Gephi), GraphML (yEd, Cytoscape), DOT (Graphviz), JSON - с позициями и цветами узлов.

## Ссылки и встраивание

Адресная строка всегда содержит текущее состояние, поэтому ссылку можно просто скопировать. Кнопка «Скопировать ссылку на вид» добавляет ещё и камеру. В ссылку попадает только то, что отличается от значений по умолчанию.

| Параметр | Что задаёт | Пример |
|---|---|---|
| `repo`, `ref` | репозиторий GitHub и ветку | `repo=DaveGamble/cJSON&ref=master` |
| `snap` | снимок `.drift` по ссылке (вместо `repo`) | `snap=project.drift` |
| `view` | вид: `includes`, `calls`, `api`, `dirs`, `stats` | `view=calls` |
| `vo` | опции видов `вид.ключ:значение` | `vo=calls.layout:td,calls.showExt:1` |
| `style` | пресет: `simple`, `cosmos`, `neon` | `style=neon` |
| `vs` | отличия от пресета `ключ:значение` | `vs=bloom:0,glow:1.2,sky:stars` |
| `lk` | подписи по типам узлов | `lk=ext:1,macro:0` |
| `lf`, `hm`, `hd` | фильтр на лету, скрытые модули и папки | `lf=src/core !tests&hm=tests&hd=src/libs` |
| `ign`, `only`, `exts`, `roots`, `maxkb`, `maxf` | фильтры файлов (списки через `;`) | `only=src/core` |
| `sel`, `focus` | выделенный узел и показ только его окрестности (глубина) | `sel=fn:main@src/main.c&focus=1` |
| `cam` | камера: кватернион поворота и приближение | `cam=0.1,0.3,0,0.95,0.8` |
| `lang`, `theme` | язык и тема | `lang=en&theme=dark` |
| `embed` | режим встраивания в iframe | `embed=1` |

С `embed=1` сайт можно встроить в страницу своего проекта через `<iframe>`: панели источника нет, а кнопка ↗ открывает полную версию с тем же видом.

## Языки

Разбор подключается плагинами (`langs.js`, реестр `CodriftLangs`); язык файла определяется по расширению.

| Язык | Расширения | Связи между файлами |
|---|---|---|
| C | `.c .h` | `#include` |
| C++ | `.cpp .cc .cxx .c++ .hpp .hh .hxx .h++ .ipp .tpp .inl .ixx .cppm` (и `.h`, если в проекте есть C++) | `#include` |
| Java | `.java` | `import` → файл класса (и `pkg.*`) |
| C# | `.cs` | `using` → файлы пространства имён |
| JS / TS | `.js .jsx .mjs .cjs .ts .tsx .mts .cts` | `import`, `require`, `export … from` |
| Python | `.py .pyi .pyw` | `import`, `from … import` |

Как языки разбираются:

- **Методы.** Получают имя `Класс.метод`. Вызовы `this.f()` / `self.f()` связываются с методом своего класса, конструкторы - с `new Foo()` / `Foo()`.
- **Колбэки.** Вызов параметра-колбэка (`cb()`) не путается с одноимённой функцией проекта.
- **Граница языков.** Вызовы разрешаются только внутри своего языка, но C и C++ видят друг друга.
- **C++.** Макросы экспорта (`class SPDLOG_API logger`) пропускаются, шаблоны и обобщения (`template<class T>`, `foo<T>(x)`) понимаются.
- **Понятия C/C++.** Прототипы, заголовки, макросы и символы `.c` показываются только в проектах на C/C++.

**Новый язык** - это объект `{ id, name, exts, parse(path, text), isHeader?, hasHeaders, oop, resolveImport?(file, imp, ctx) }`, зарегистрированный через `CodriftLangs.register(...)`:

- для C-подобного синтаксиса есть конструктор `makeBraceLang(cfg)`;
- `parse` возвращает тот же формат, что и `CParser.parseFile`: `includes`, `funcs` (с `name`, `container`, `sig`, `calls`, `ids`, `memberCalls`, `doc`), `types`, `vars`, `macros`, `decls`;
- модель, виды, статистика и экспорт подхватывают язык сами.

## Как это устроено

| Файл | Что делает |
|---|---|
| `index.html` | разметка и стили интерфейса, загрузка библиотек с CDN |
| `parser.js` | разбор C: комментарии и литералы, препроцессор, функции, типы, переменные, вызовы |
| `langs.js` | реестр языков и разбор C++, Java, C#, JS/TS, Python |
| `app.js` | загрузка источников, модель проекта, виды, 3D-сцена, раскладка, статистика, экспорт, интерфейс |
| `manifest.webmanifest`, `icon-*.png` | веб-приложение (значок на экране «Домой») |

**Путь данных:** источник → список файлов (с фильтрами) → разбор каждого файла плагином своего языка → модель проекта (файлы, папки, функции, макросы, типы, подключения и вызовы) → граф выбранного вида → раскладка → отрисовка.

**Разбор C (`parser.js`).** Лёгкий эвристический, без полного препроцессора:

- корректно вырезает комментарии и литералы;
- разбирает `#include` и `#define`, а также условную компиляцию: ветки `#if 0` и `#else` не участвуют в разборе тел;
- находит объявления и определения функций (включая атрибуты `[[...]]`), `struct` / `union` / `enum` / `typedef`, глобальные переменные и вызовы внутри тел функций;
- разворачивает вызовы через макросы до реальных функций;
- берёт описания из комментариев над объявлениями или в конце строки.

**Раскладка** считается в отдельном потоке (Web Worker, `d3-force-3d`), поэтому интерфейс и камера не тормозят даже на графах в десятки тысяч узлов. Как это работает:

- «Дерево» и «Радиально» - мягкие силы к уровню, а уровни - обход в ширину от узлов без входящих связей.
- Узлы не пересекаются: столкновения расталкивают их сферы, а оставшиеся пересечения в конце разводятся напрямую.
- Позиции из потока сглаживаются, поэтому движение плавное, даже если поток перегружен.
- Если поток не запустился, раскладку считает основной поток.

**Отрисовка** - three.js и 3d-force-graph. Что делает её быстрой:

- **Мало вызовов отрисовки.** Все узлы - один экземплярный меш, все связи - один буфер линий.
- **Кадр только по необходимости.** Кадр рисуется, только когда что-то меняется, а в покое анимация засыпает.
- **Отсечение.** Невидимые узлы не отправляются на видеокарту.
- **Плотные графы.** Линии сами приглушаются, у фоновых импульсов есть бюджет точек, MSAA сглаживает тысячи тонких линий.
- **Выделение крупных узлов.** Узел с сотнями связей подсвечивается отдельным слоем, а не сотнями объектов.

**Состояние** (настройки, фильтры, вид) хранится в `localStorage` браузера и в адресной строке. Токен GitHub никуда не сохраняется.

**Зависимости** (CDN jsDelivr, версии зафиксированы):

- `three@0.174.0` (с `UnrealBloomPass`) и `3d-force-graph@1.77.0`;
- `d3-force-3d@3.0.5` - в потоке раскладки;
- по требованию: `fflate@0.8.2` (zip), `mp4-muxer@5.1.3` и `gifenc@1.0.3` (видео).

Неиспользуемая сборка `three/webgpu` заменена заглушкой через import map, чтобы на странице не было второй копии Three.js.

## Ограничения

- **GitHub без токена.** API даёт 60 запросов в час на IP. Одна загрузка проекта - это один запрос (список файлов), а содержимое читается через `raw.githubusercontent.com`. Если лимит исчерпан, список файлов берётся через jsDelivr; но репозитории больше 50 МБ jsDelivr не отдаёт - тогда нужен токен или снимок `.drift`.
- **Эвристический разбор, а не компилятор:**
  - код, который генерируют макросы (функции через `DEFINE_X(name)`), не распознаётся;
  - вызов через указатель на функцию, хранящийся в локальной переменной или параметре, не разрешается (через поля структур - разрешается);
  - в языках с классами вызов `obj.method()` связывается по имени метода, если таких методов немного.
- **Браузер.** Нужен современный браузер с WebGL2 (Chrome, Edge, Firefox, Safari последних версий). Для MP4 нужны WebCodecs, без них пишется GIF.
- **Большие проекты.** Число файлов по умолчанию ограничено 5000 (меняется в фильтрах). Большие графы (десятки тысяч узлов и связей) работают, но им нужна дискретная видеокарта. Если FPS низкий, а время кадра маленькое, браузер, скорее всего, рисует на встроенной видеокарте - сайт об этом предупредит.
